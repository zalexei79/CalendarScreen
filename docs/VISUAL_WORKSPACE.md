# Локальная визуальная рабочая среда

Запуск: `npm run project:desk` → `http://127.0.0.1:5173/project-desk.html`. Начальный экран — календарь, а карта файлов доступна отдельно. Облачные права администратора и доступ к данным пользователей не меняются: локальные файлы редактируются с разрешения владельца ПК; реальные данные календаря по-прежнему защищены обычной сессией и серверными правилами.

## Главный путь: «Посмотреть» → локальное сохранение → push

Главная кнопка «Посмотреть» открывает отдельное браузерное окно с настоящим календарём. Если браузер его заблокировал, разрешите всплывающие окна для локального адреса. Оформление, свои кнопки и голосовые команды передаются прямо из текущего черновика, в том числе ещё не записанного на диск. Они не берутся с опубликованного сайта и не отправляются в Supabase. Код выполняется только из сохранённых файлов рабочей копии; несохранённый текст исходника сначала нужно сохранить. Панель не использует eval для вставленного кода: изменения файлов собираются Vite и выполняются как обычный код приложения с доступом его сессии. Проверяйте код перед запуском.

1. Внесите изменения в песочнице → «Посмотреть». Окно можно открыть без подключённой папки. Первый выбор папки после редактирования сохраняет текущий черновик, а не заменяет его содержимым диска. При переподключении уже открытого проекта с правками есть предупреждение.
2. По умолчанию нажатия не выполняют действия аккаунта. Для функциональной проверки отдельно включите «Разрешить действия в моём аккаунте». Это реальные данные, не тестовая база; обычные права и подтверждения приложения сохраняются. Блокировка нажатий не блокирует фоновые запросы обычного приложения. Сохранённый код исполняется с правами сессии; для экспериментальных изменений используйте тестовый аккаунт.
3. «Сохранить локально» → проверить список файлов → «Создать копии и сохранить оформление». Подключите правильную папку, если она ещё не выбрана. Ошибка конфликта не затирает файл. Сохранение — не push.
4. Отметьте «Я проверил эту версию». Мастерская привяжет подтверждение к текущему HEAD и хешам изменённых файлов. «Подготовить push» открывает существующие защищённые инструменты: выбор файлов → комментарий → подтверждение словом ПУБЛИКОВАТЬ → сборка и тесты → commit выбранных файлов → push. Выбор не делается автоматически. Если состояние файлов/HEAD отличается от проверенного, подготовка блокируется. Сервер повторно сверяет HEAD и выбранные хеши до и после сборки.
5. Push не подтверждает выпуск Render: опубликованный HTTPS-сайт проверяется отдельно.

Пока окно открыто, его оформление и команды — снимок на момент «Посмотреть». Изменения в редакторе делают снимок устаревшим: сохранить или подготовить push из него нельзя. «Обновить просмотр» берёт текущий черновик и заново загружает календарь. Сохранённые файлы кода также обновляются Vite; они не заморожены в отдельный исполняемый пакет. Изменение кода через встроенный редактор делает снимок устаревшим, а изменение файлов извне дополнительно проверяется перед push по хешам. После нового сохранения/изменения подтверждение просмотра сбрасывается.

Ctrl/Command+S в редакторе открывает обзор локального сохранения; при несохранённом исходнике предлагает сначала сохранить именно его. В отдельном результате сочетание работает и над календарём, и над оболочкой окна. Оно не запускает push. Пробел, Ctrl+0 и Ctrl+1 мастерская не перехватывает.

## Меню элемента

- **Элемент** — назначение, цепочка действия, видимость, название новой кнопки и переход к исходнику. Подписи/иконки штатных элементов меняются в их компонентах и переводах, а не обещаются как поддержанные визуальные поля.
- **Поведение** — существующие обработчики/переходы и конструктор голосовых команд. Новые серверные операции требуют кода и проверок прав.
- **Расположение** — зоны новых кнопок, размеры, сдвиги и порядок внутри ряда, отдельно для телефона и ПК. Это не произвольное перемещение React-узла между компонентами.
- **Стиль темы** — родной вид по умолчанию, «Акцент темы» или «Спокойный». Семантический параметр emphasis ограничен перечислением; CSS использует токен темы. Точные цвета, размер текста и скругления скрыты в «Дополнительно».
- **Код** — связи с реальными исходниками и защищённый редактор файла.

Для окон и кнопок используются короткие переходы: появление 240–320 мс, отклик нажатия 140 мс. Нет постоянного движения полотна; prefers-reduced-motion отключает новые анимации. Рабочий календарь не получает новый глобальный стиль без вашего изменения его черновика.

## Работа с окнами

Локальная мастерская теперь открывает свободную песочницу. Нажмите элемент календаря в режиме редактирования: рядом сразу появится немодальное окно с вкладками «Элемент / Поведение / Расположение / Стиль темы / Код». Календарь остаётся доступным. Меню элемента по-прежнему позволяет перейти к логике или явно выполнить настоящее действие. Если элемент не виден, используйте выбор «Элемент» над полотном.

За заголовок можно передвигать календарь и окна редакторов. Булавка оставляет окно открытым при выборе другого элемента; закреплённое окно всё ещё можно двигать. Поля в закреплённом окне относятся именно к указанному в его заголовке элементу. Незакреплённое окно заменяется новым выбором. Доступно до 8 закреплённых окон; лишнее не вытесняет уже закреплённые. «Собрать окна» возвращает понятную раскладку. Фон можно перетаскивать, также доступны полосы прокрутки. На узком экране окна располагаются вертикально.

Позиции окон сохраняются только в браузере; исходники, данные аккаунта и тексты команд в хранилище раскладки не записываются. После перезагрузки элементы нужно выбрать заново. Оформление и команды сохраняйте отдельно через «Сохранить в проект». Изменение позиции окна не является изменением оформления и не входит в Ctrl+Z оформления.

«Код» открывает исходники прямо в окне. Одновременно активен один редактор исходного текста: переход к другому элементу или закрытие требует подтверждения, если текст не сохранён. Закреплённое окно со связями остаётся, а его текстовый редактор можно активировать снова кнопкой. Подключите папку проекта — станут доступны чтение, редактирование, сравнение и сохранение с резервной копией. Для локального React-элемента редактор пытается найти файл и строку по отладочной информации React/Vite. Это не гарантировано для каждого узла и библиотеки. Проверяется совпадение с каталогом проекта: произвольный путь из iframe не открывается. Если точной связи нет, показывается описание зарегистрированного модуля. DOM-селектор можно добавить в общий CSS. При перестройке DOM такой селектор иногда требует обновления.

## Масштаб и отмена

- Локально календарь открывается в масштабе 100%, а не уменьшенным до высоты окна. Обычное колесо прокручивает календарь, Ctrl/Command+колесо над предпросмотром меняет масштаб от 25 до 250%. Есть кнопки −/+, «Подогнать» и 100%. Масштаб не изменяет CSS или данные приложения. Точка приближения привязана к курсору; при достижении края прокрутка ограничивается браузером.
- Эти правила одинаковы в редактировании и проверке приложения. Shift+колесо не перехватывается редактором и сохраняет браузерную прокрутку. Над фоном прокручивается полотно, над окном редактора — содержимое этого окна. Ctrl+колесо для масштаба используйте над календарём, а не над текстовыми полями.
- Ctrl/Command+Z вне текстового поля отменяет последнее изменение оформления, Ctrl/Command+Shift+Z или Ctrl+Y возвращает. В текстовом поле работает его стандартная отмена ввода. Кнопки отмены есть также в конструкторе функций и исходниках. До 50 шагов в текущем редакторе.
- Истории разных документов независимы. При открытии другого файла история текста сбрасывается. Отмена после сохранения меняет черновик; чтобы вернуть файл на диске, сохраните его ещё раз. Undo не отменяет запросы к реальным данным, commit, push или опубликованный релиз.

## Новогодний стиль без подписки на ИИ

1. «Подключить папку проекта» → выберите ту же рабочую копию, где запущена мастерская.
2. «Тема и CSS» → вставьте CSS, созданный самостоятельно или с любым GPT. HTML/JS и React-код в это поле не вставляются. Зимний пример — необязательная отправная точка, он не применяется автоматически.
3. «Посмотреть календарь» → оцените телефон и ПК. CSS применяется сразу к предпросмотру, не к админке. Для базовых элементов подходят `.dayris-header`, `.calendar-section`, `.calendar-days-grid`, `.calendar-voice-button`; точные классы смотрите в исходниках.
4. «Сохранить в проект» → подтвердите изменённые файлы. Тема сохраняется в `src/features/appearance/calendar-custom.css`, визуальные настройки — в `src/features/appearance/siteDesign.json`. Каждый файл сначала копируется в `.dayris-project-backups`, внешнее изменение блокирует перезапись. Два файла не записываются атомарно: при частичном успехе сообщение перечисляет уже сохранённые файлы, оставшийся черновик сохраняется в редакторе.
5. «Сборка и публикация» → проверить сборку, обновить Git, выбрать только свои файлы, комментарий → подтвердить commit/push. Render выпускает сайт отдельно: после push проверьте HTTPS-сайт и обновление установленной PWA.

CSS доверенный, не sandbox: способен скрыть кнопки, перекрыть интерфейс, загрузить внешние шрифты/изображения. Не вставляйте секреты, не скрывайте защитные подтверждения, не считайте скрытие элемента контролем прав. Сборка проверяет синтаксис CSS, но не доказывает хороший внешний вид, поэтому нужен предпросмотр. Для возврата до сохранения есть отмена; после сохранения — копия файла или Git.

После сохранения визуальных параметров локальный `siteDesign.json` получает `overrideCloud: true`. После выпуска локальные параметры становятся основными, а облачная админка показывает предупреждение: её публикация не перекроет файл. Для возврата к облачному управлению установите `overrideCloud: false` в исходнике и выпустите новую сборку. Сохранение только CSS этот флаг не меняет.

## Консоль

Под календарём — ошибки JavaScript, необработанные Promise и `console.error/warn` локального предпросмотра (не более 40 сообщений). Журнал сборки/Git находится в окне публикации. Это не произвольный shell/JS-интерпретатор. Сообщения могут содержать данные вашего настоящего аккаунта: не публикуйте их без проверки. Для новых мини-экранов с JavaScript есть отдельный «Конструктор функций» с изоляцией, описанный в `LOCAL_FUNCTION_STUDIO.md`.

Это не универсальный автоматический рефакторинг всего приложения. Перенос узлов между произвольными React-компонентами, новые серверные API и изменения схемы базы требуют редактирования соответствующего кода и профильных тестов. Инструменты дают прямой доступ к этим исходникам, не отменяя проверок данных и прав.
