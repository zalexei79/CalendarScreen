# Следующий интерфейс окна элемента — предложение

Статус: новое меню и отдельное окно «Посмотреть» реализованы в локальной студии. Актуальный сценарий и ограничения описаны в VISUAL_WORKSPACE.md. Это не универсальная визуальная схема произвольной логики. Перемещение окна меняет рабочее место, а не расположение кнопки внутри приложения.

## Основное окно

В заголовке: понятное имя элемента, закрепление, закрытие. Ниже: назначение одной строкой и краткий путь действия. Например: микрофон → распознавание → разбор команды → действие/подтверждение. Состояния и серверные ограничения не скрываются оформлением.

1. **Элемент.** Название, подпись, иконка, доступность, состояния «обычно / загрузка / ошибка». Только поддержанные компонентом изменения; неподдержанный случай явно ведёт к исходнику.
2. **Поведение.** Что происходит после нажатия, какой экран открывается, какие команды распознаются, что требуется для выполнения. Голосовые фразы используют существующие ограниченные действия. Произвольные алгоритмы и серверные операции меняются в связанных исходниках, не исполняются вставкой JS в админскую сессию.
3. **Расположение.** Телефон/ПК, блок родителя, доступные зоны размещения, выравнивание и отступы. Размер — по содержимому или из поддержанного набора. Перенос произвольного React-узла между компонентами не обещается без отдельной реализации.
4. **Стиль темы.** По умолчанию наследовать тему. После реализации семантических вариантов выбирать «обычный / основной / второстепенный» вместо ручных цветов. Компактность и размер иконки — только если компонент поддерживает такие настройки. Индивидуальные CSS-правки и точные размеры остаются в закрытом разделе «Дополнительно».

Вместо длинного списка исходников на первом экране — действие «Где это в проекте» с назначением файла. Точный код, сравнение и сохранение открываются по запросу через существующий защищённый редактор.

Перед сохранением показывать понятный список: какой элемент изменён, что поменялось, телефон/ПК, какие файлы будут записаны. Сохранение на диск, сборка, push и подтверждённый выпуск — разные состояния. Не обещать автоматическое сохранение произвольных React-изменений через параметры темы.

## Управление

Уже доступно: обычное колесо — прокрутка; Ctrl/Command+колесо над календарём — масштаб; Ctrl+Z — отмена оформления; Ctrl+Shift+Z/Ctrl+Y — возврат оформления; в текстовом редакторе своя история. Undo не отменяет изменения пользовательских данных, перемещение окон или публикацию.

По решению пользователя не добавляются пробел+перетаскивание, Ctrl+0 и Ctrl+1. Ctrl+S открывает обзор локального сохранения, не публикацию. Его обработка не записывает несохранённый текст исходника вместо пользователя. Рядом с командами остаются доступные кнопки.
