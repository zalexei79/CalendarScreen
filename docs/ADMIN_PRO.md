# Управление PRO

Админка → **PRO** или `/admin.html?section=pro`.

Также: **Пользователи → карточка → Открыть PRO** (или вкладка PRO внутри карточки). Выбранный аккаунт не меняется: выдача, продление и отключение работают в том же контексте. Быстрые сроки 30/90/365 дней только заполняют форму; сохранение по-прежнему требует причины и подтверждения. Календарь, профиль и остальные данные доступны в соседних вкладках. В карточке календаря день раскрывает отдельную сводку со всеми счетами и валютами без смешивания сумм. Иллюстрация пустого состояния декоративная, статистика берётся из реального ответа сервера, а «Последний вход» не означает присутствие онлайн.

- По умолчанию показаны активные аккаунты: подарки/рефералы/промо из `pro_entitlements` и платёжный PRO Lemon Squeezy из `pro_subscriptions`. Семантика совпадает с серверным `get_my_pro_status`, включая активную подписку без даты окончания. Для неё остаток не выдумывается.
- Для выдачи выберите «Все пользователи», найдите имя/email/UUID. Telegram-аккаунт без email находится по UUID. ID из обращения не получает PRO автоматически.
- Выберите дни/годы или «77 лет» и подтвердите. Заметка при выдаче и продлении необязательна (до 500 символов); при отключении требуется причина от 5 символов. Пустая заметка записывается как NULL, без выдуманного текста; аудит администратора, аккаунта и значений до/после остаётся обязательным. Это именно календарные годы, не приблизительное количество дней. Новый доступ `source=admin` начинается сейчас и заканчивается через выбранный срок после последнего известного окончания доступа (или от текущего времени).

## Активность пользователей

### Рабочее место пользователей

На ПК список и поиск находятся слева и прокручиваются отдельно от карточки справа. Поиск работает по вводу с небольшой задержкой; Enter/кнопка поиска выполняют его сразу. Быстрые фильтры: все / записи за 7 дней / без записей. Дополнительные сроки и сортировка — в «Фильтры и сортировка». «Лента всех пользователей» возвращает общий поток.

Карточка открывается на «Обзоре»: количество текущих облачных записей, время входа, регистрация, статус PRO и последние пять записей. Неизвестные значения не заменяются нулями. «Открыть запись» выбирает аккаунт, раздел данных, месяц и день из записи и выделяет её; чужой аккаунт или некорректная дата не используются для навигации. Остальные разделы (календарь, все данные, профиль, PRO, история) доступны рядом. На телефоне список, общая лента и карточка показаны отдельными экранами, возврат — «К списку пользователей». Серверные права и подтверждение изменений не меняются.

Раздел пользователей по умолчанию показывает ленту последних облачных записей. Фильтры списка: все / записи за 24 часа, 7, 30 дней / без записей; сортировка по последней записи, входу или регистрации. Фильтры ленты по периоду и типу независимы от фильтров списка. В карточке доступна вкладка «Последние записи» только выбранного аккаунта.

Источники: календарь (`trades`, включая импортированные сделки), кошелёк, планы и заметки. Сортировка использует `updated_at`, если есть, иначе `created_at`; дата, выбранная человеком в календаре, не выдаётся за время сохранения. У старых записей без временной метки показано «Время сохранения неизвестно», они не считаются активностью за последние дни. «Без записей» означает отсутствие текущих облачных записей этих четырёх типов, а не отсутствие входов или удалённых в прошлом данных. Суммы и валюты не объединяются. Это не слежение за онлайн-присутствием и не журнал всех действий на устройстве. Схема и RPC: `202610260002_admin_user_activity.sql`; функции защищены существующими правами просмотра пользователей.
- «Отключить PRO» завершает все текущие/будущие записи `pro_entitlements` и локально переводит активные платёжные подписки Lemon Squeezy в `expired`. Записи не удаляются. Это **не возврат денег и не отмена автоплатежа**. Для отмены платежей используется кабинет провайдера. Новый webhook провайдера/покупка/реферальное начисление могут снова активировать PRO; это не постоянный бан.
- Аккаунту может потребоваться обновить календарь для повторного запроса PRO. Здесь нет принудительного выхода из всех сессий.

## Защита и выпуск

Миграция `202610200001_admin_pro_management.sql` требует существующие таблицы подписок, миграции админки и Google-ограничения `202610150003_admin_google_access.sql`. Никакие дополнительные административные права автоматически не выдаются. Чтение требует `site_admin_require()`, изменения — `site_admin_require(true)`; подписка самого администратора не даёт этих прав. Прямые права к таблицам не расширяются.

RPC: `admin_list_pro`, `admin_pro_state`, `admin_change_pro`. Перед записью сервер сравнивает подтверждённый снимок обоих источников с текущим и сериализует короткую транзакцию с конкурентными записями. При конфликте нужно обновить данные и повторно подтвердить. До/после и причина атомарно сохраняются в `site_admin_audit`; служебные платёжные идентификаторы не отдаются в интерфейс.

При рассинхронизации журнала старых миграций нельзя выполнять массовый `db push --include-all`: применяйте только проверенный новый файл и регистрируйте только его версию. Проверки: `node --test tests/admin-pro-db.test.mjs tests/admin-pro-model.test.mjs`, `npm run build`, `node tests/admin-pro-ui-check.mjs`, `node tests/admin-users-ui-check.mjs`.
