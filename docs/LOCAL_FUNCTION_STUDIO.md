# Локальный конструктор функций DAYRIS

Запуск: `npm run project:desk`, затем `http://127.0.0.1:5173/project-desk.html` → **Конструктор функций**. Нужен Edge или Chrome на ПК, Node.js и установленные зависимости проекта. Подписка на ИИ не нужна. Это локальная вкладка, а не новая удалённая админка. Телефонная админка не меняется.

## Полный цикл

1. Подключите именно папку, из которой запущена мастерская. Проверяется идентификатор рабочей копии.
2. Добавьте функцию: появится шаблон кнопки со счётчиком на своём экране. Задайте название и назначение.
3. Выберите вид телефона или ПК. Настройте цвет, размеры и размещение отдельно для каждого. «Выбрать место на календаре» позволяет указать координаты нажатием. Для обычного элемента шапки выберите расположение «В шапке календаря».
4. Настройте цепочку нажатия: сообщения → свой экран, переход **или** действие DAYRIS. Последнее действие должно завершать цепочку. Можно оставить только сообщение. Подключены настройки, голосовой помощник, следующий/предыдущий месяц и сегодня; используются существующие кнопки и их проверки, без обхода прав. Все действия видны в форме.
5. Для новой логики скопируйте «Задание для GPT». Вставьте ответ в HTML, CSS и JS. Поддерживается обычный браузерный JavaScript, не React/JSX, npm/import или внешние библиотеки. Код запускается после HTML при открытии своего экрана.
6. Нажмите «Обновить предпросмотр», затем свою кнопку в календаре. Проверьте экран на телефоне и ПК, клавиатуру, журнал ошибок. В тестовом режиме запросы переходов только записываются в журнал. Сам календарь — настоящий локальный DAYRIS и может работать с данными вошедшего аккаунта.
7. «Проверить и сохранить функции» → подтверждение. Меняется только `src/features/extensions/extensions.json`. Сначала создаётся копия в `.dayris-project-backups`. Изменение файла другой программой блокирует перезапись. До сохранения можно скачать JSON черновика или заново открыть файл.
8. Проверьте сборку. Обновите список Git, выберите файл функций, добавьте комментарий и подтвердите публикацию. После первого внедрения конструктора последующие функции обычно требуют изменения только этого JSON. Git-публикация делает build, базовые тесты, commit выбранных файлов и push; Render выпускает сайт отдельно. Проверяйте HTTPS-сайт после выпуска.

## API мини-экрана

```js
dayris.notify('Готово'); // сообщение рядом с экраном; в студии также журнал
dayris.navigate('/?view=example'); // запрос перехода, не создание нового маршрута
dayris.navigate('https://example.com/'); // внешний переход с подтверждением в DAYRIS
dayris.close(); // закрыть экран
```

Используйте `document.querySelector` только для своего HTML, `addEventListener` для событий, переменные JS для расчётов и временного состояния. URL не создаёт экран или обработчик автоматически: для них используйте свой экран или подключайте маршрут в исходниках.

## Границы и безопасность

- Мини-экран работает в `sandbox="allow-scripts"` с непрозрачным origin. Нет `allow-same-origin`, доступа к родительскому DOM, Google/Supabase-сессии, файловой папке, cookies и локальному хранилищу DAYRIS. Доверенная внешняя оболочка ограничивает навигацию вложенного мини-экрана через CSP `frame-src about:`, а его собственная CSP блокирует fetch, формы, вложенные фреймы и внешние ресурсы. Проверяется реальным браузерным тестом в Edge; другим браузерам нужна дополнительная проверка. Авторитетные действия не выполняются через сообщения кода. Основа изоляции: [MDN: iframe srcdoc и sandbox](https://developer.mozilla.org/en-US/docs/Web/API/HTMLIFrameElement/srcdoc).
- Это не конструктор всех возможных серверных функций: запись календаря, кошелька, PRO-права, API и SQL требуют отдельного проверенного кода/интеграции с сервером. Не добавляйте прямой доступ к токену в мост сообщений. Сервер обязан проверять пользователя и права независимо от UI.
- Состояние мини-экрана временное и теряется при закрытии. Не выдавайте его за сохранение данных. Бесконечный цикл или тяжёлый JS может подвесить вкладку: sandbox не заменяет ревью кода и не гарантирует лимит процессорного времени. Попросите GPT объяснить код, проверьте его перед выпуском. Код владельца находится только во внутреннем непривилегированном iframe. Внешняя same-origin оболочка содержит лишь доверенный CSP/relay и экранированный `srcdoc`; нельзя вставлять пользовательский HTML/JS прямо в оболочку или давать внутреннему iframe `allow-same-origin`.
- Код и описания входят в публичную сборку. Не помещайте сюда ключи, пароли или пользовательские данные. Скрытие кнопки/выключение функции — не контроль доступа к данным.
- До 20 функций, до 8 шагов, до 64 К символов на блок кода, до 512 КБ на конфигурацию. Полная сборка отклоняет неверный манифест. JS проверяется реальным запуском в тесте: сборка JSON не доказывает корректность поведения кода.
- Для отмены до публикации восстановите нужный файл из резервной копии через карту/исходники. После публикации восстановите предыдущую версию JSON и выпустите новый commit. Git-история остаётся основным журналом выпусков.
