# Рассылка от создателя

Админка → «Рассылка» либо «Пользователи» → карточка → «Написать пользователю».
Выберите аккаунт или всех, заполните заголовок и текст. Push и подарок PRO включаются отдельно. Перед отправкой проверьте предпросмотр и подтвердите получателей. Подготовка ничего не отправляет.

Внутренние сообщения сохраняются у получателя в настройках → «Сообщения». Непрочитанные показываются при открытии приложения; чтение не удаляет историю. Последнее личное сообщение к подарку также доступно в PRO. Текст отображается как обычный текст, HTML и скрипты не исполняются.

## Карточки и ответы

В «Рассылке» есть редактор надписей и песочница. Нажатие на текст предпросмотра переводит к соответствующему полю. Один и тот же компонент рисует карточку в редакторе и у получателя. Переключатели показывают телефон/компьютер и карточку/переписку без сетевой отправки сообщения.

Настраиваются заголовок, текст, подпись отправителя, кнопки для подарка и обычного сообщения, переход в чат, подпись снизу, срок PRO (`{date}` подставляет настоящую дату), закрытие, сохранение, значок, тема и акцент. Пустые необязательные подписи скрываются. По умолчанию без подарка — «Хорошо», с подарком — «Спасибо». Настройки фиксируются вместе с предпросмотром и отправкой; последующие изменения не меняют уже отправленную карточку. Общий чат использует стандартные подписи интерфейса; прежняя отдельная форма ответа заменена перепиской.

«Ответить» открывает общий диалог. Админка → «Чаты» показывает список разговоров с поиском и фильтром непрочитанных. «Написать пользователю» из карточки аккаунта открывает тот же чат. Получатель открывает его через настройки → «Сообщения», даже если раньше ему ничего не отправляли. Обычное сообщение отправляется прямо из поля ввода, без создания новой рассылки вручную. Кнопка подарка в шапке чата открывает редактор личной рассылки/PRO с выбранным пользователем.

В общей ленте видны все прежние рассылки, подарки и ответы без копирования записей. Сообщения идут по времени; старые загружаются по курсору. Открытый чат обновляется каждые 3 секунды, список диалогов — каждые 5 секунд. Скрытая вкладка не опрашивает сервер. Новые сообщения не прокручивают ленту, если человек читает историю. Галочки означают отправку и сохранённое сервером прочтение. Статусы «онлайн» и «печатает» не имитируются.

Сообщение чата ограничено 2000 символами, пользователь — 30 отправками в минуту, администратор — 60. Повтор запроса с тем же UUID и текстом возвращает прежнее сообщение. Пользователь может читать и отмечать только свой диалог; назначенный Google-администратор с `viewUsers` читает чаты, с `editUsers` также пишет и отмечает прочтение. Отмечаются входящие сообщения загруженной ленты при просмотре её конца. Административное сообщение ставится в существующую очередь push при наличии разрешённых устройств; пользовательские сообщения отображаются в админке. Реальных сообщений при разработке отправлять не требуется.

Право PRO по-прежнему рассчитывается сервером. Системный вид push задаётся ОС; редактируются только его заголовок и текст. Старые RPC ответов сохранены для совместимости с ранее открытыми версиями приложения.

## Серверные правила

- Отправка требует назначенного Google-администратора с правом редактирования пользователей; просмотр истории — права просмотра.
- Получатели фиксируются сервером при подготовке. «Все» включает отправителя; новые регистрации после предпросмотра не добавляются. Лимит 5000 аккаунтов, 30 подготовок в час, срок подтверждения 1 час.
- PRO добавляется к имеющемуся сроку через существующую серверную выдачу. Сообщение, подарки и аудит записываются одной транзакцией; повтор того же подтверждения не дублирует выдачу. Отправку нельзя отменить.
- Каждый пользователь читает и отмечает только собственные сообщения. Клиент не получает ключи push и сервисный ключ.
- Push обрабатывает существующий cron `send-reminders`: до 10 устройств за запуск. Он необязателен; нужны разрешение ОС и активная подписка. Прочитанные сообщения и очередь старше суток не отправляются. Новые устройства могут добавляться в течение суток.
- «Принято службой» означает принятие push-провайдером, а не гарантированное получение или чтение. Неопределённые сетевые результаты не повторяются автоматически. Повторы при 429 ограничены четырьмя попытками.
- Персональный подарок заменяет стандартное уведомление о выдаче PRO, чтобы не было двух сообщений.

## Проверки и развёртывание

`node --test tests/creator-messages-db.test.mjs tests/creator-messages-push.test.mjs tests/pro-notifications.test.mjs`

`npm run build`, затем `node tests/creator-messages-ui-check.mjs` и существующие проверки пользователей/PRO.

Для первой установки применить `202610290002_creator_messages.sql`, затем `202610290003_message_cards_and_replies.sql` и `202610290004_account_messenger.sql`, обновить `send-reminders` и frontend. Для уже работающего редактора нужна только новая миграция `202610290004`. Не запускать весь старый набор миграций повторно. Проверки используют локальную базу и подставные аккаунты; реальные рассылки или подарки для проверки не нужны.
