# DAYRIS: как самостоятельно находить и менять проект

Этот документ хранится в проекте и читается без подписки на ИИ. В админ-панели есть вкладка **Проект**: дерево, поиск по назначению, подсказки и прямые связи импортов. Это карта исходников и текстовый редактор, а не автоматическое программирование.

Для добавления своих кнопок и мини-экранов с кодом используйте локальную вкладку **Конструктор функций**. Полный цикл, API и ограничения: [LOCAL_FUNCTION_STUDIO.md](LOCAL_FUNCTION_STUDIO.md).

## Быстрый старт на ПК

### Сразу с предпросмотром, сборкой и кнопками Git

Один раз откройте PowerShell в папке `D:\ai-trade-journal`:

```powershell
npm run project:desk
```

Откройте `http://127.0.0.1:5173/project-desk.html` в Edge/Chrome. Оставьте терминал работающим; для остановки нажмите Ctrl+C. Порт 5173 должен быть свободен: одновременно второй `npm run dev` не нужен. Если зависимостей ещё нет, сначала установите их обычным способом для проекта (`npm ci`). Интернет нужен для установки зависимостей, Google/Supabase и push, но не для самого текстового редактора и локальной карты.

В локальной мастерской нет требования входить в админский Google-аккаунт: доступ ограничен текущим ПК и разрешением папки. Сам календарь в предпросмотре использует обычную авторизацию DAYRIS; Google должен разрешать callback `http://localhost:5173` / выбранный localhost-адрес в Supabase. Если вход по 127.0.0.1 не настроен, откройте мастерскую через `http://localhost:5173/project-desk.html` с разрешённым callback. Для публичной HTTPS-админки проверка роли Google остаётся прежней.

Внутри:

Верхняя кнопка **Визуально** открывает календарь с контекстным меню элементов и инспектором «Вид / Логика / Связи». Нажмите микрофон → «Логика и команды», чтобы добавить фразу к существующему действию. Переход из «Связей» открывает нужный исходник в **Карте и исходниках**, сохраняя подключённую папку. Облачное оформление и фразы сохраняются назначенным администратором в Supabase отдельно от Git-выпуска кода. Встроенный каталог голосовых возможностей доступен для изучения; совершенно новая функция по-прежнему требует реализации и тестов в исходниках.

1. **Подключить папку проекта** — выберите именно копию, в которой запущена команда. Специальный локальный идентификатор проверит соответствие, чтобы редактирование одной копии не привело к сборке другой.
2. Отредактируйте и сохраните файл. Vite автоматически обновит **Локальный предпросмотр**; доступны вид телефона и ПК, перезагрузка и открытие результата отдельно. Изменения исходника видны после сохранения, а не во время набора несохранённого текста. Предпросмотр выполняет код проекта и работает с аккаунтом, который вошёл в локальный календарь.
3. **Проверить сборку** — выполнит `npm run build` и базовые тесты безопасности проекта/админки, покажет результат и журнал. Профильные тесты нужного экрана проверяйте дополнительно.
4. **Обновить изменения Git** → выберите только нужные файлы → введите комментарий commit → **Подготовить публикацию**. Ничего не выбирается автоматически. Для подтверждения введите `ПУБЛИКОВАТЬ`.
5. **Собрать, сделать commit и push** — повторно соберёт проект, выполнит базовые тесты и проверку diff, создаст commit только выбранных файлов и отправит в `origin/main`. Неподходящая ветка/remote, готовый staging, устаревшие хеши, ошибка сборки/тестов или изменение файлов во время операции остановят отправку. Новые source-файлы можно отправлять; удаления/переименования, бинарные файлы, lock-файл и секреты требуют обычного Git.
6. Дождитесь выпуска Render и откройте ссылку **Проверить опубликованный сайт**. Успешный push сам по себе не означает, что сервер уже обновлён.

Если commit создан, но push не прошёл, его хеш останется в журнале. Исправьте сеть/авторизацию Git и выполните `git push origin main` в терминале; не создавайте дублирующий commit. Если возникла ошибка после staging, разберите `git status` вручную: мастерская не отменяет подготовленные изменения автоматически. После потери связи не запускайте повторную публикацию вслепую — текущая операция может продолжаться.

Локальный сервер слушает только 127.0.0.1. Командные API требуют правильный Host, Origin и случайный токен текущего запуска; опубликованный сайт не может использовать их напрямую. Нет API произвольных shell-команд. Не открывайте сетевой доступ к этому серверу и не используйте недоверенные исходники. Временный `.dayris-project-desk.json` не содержит ключей доступа и исключён из Git. Резервные копии локальны.

### Только карта и редактор из HTTPS-админки

1. Откройте установленную DAYRIS Admin или `/admin.html` на своём HTTPS-сайте в Edge/Chrome. Войдите своим назначенным Google-аккаунтом.
2. Откройте **Проект → Подключить папку проекта** и выберите `D:\ai-trade-journal` (не `src`, не весь диск). Браузер сам попросит разрешение.
3. Найдите нужную папку или файл. До подключения показывается карта версии сайта; после подключения текст читается с вашего ПК. Он не загружается в Supabase или другой сервер.
4. Нажмите **Редактировать локально**. Измените текст, затем **Проверить и сохранить**. Сравните «Было / Станет»; для чувствительных файлов подтвердите понимание риска.
5. **Создать копию и сохранить файл** сначала создаст `.dayris-project-backups/<дата>/<путь файла>`, затем запишет исходник. Если копия не создалась или исходник изменился в другой программе, сохранение остановится.
6. Для отмены несохранённого изменения нажмите **Заново открыть файл**. Для восстановления сохранённого — откройте резервную копию обычным редактором, верните её содержимое в исходник и проверьте сборку. Резервные копии не отправляются в Git. Не удаляйте их, пока не убедитесь, что всё работает.

Firefox/Safari без поддерживаемого выбора папки показывают карту и инструкции, но не прямое редактирование файлов. Разрешение папки относится к браузеру и этому ПК; оно не даёт телефону доступ к диску компьютера. После закрытия вкладки папку нужно выбрать снова. «Отключить» сбрасывает доступ в текущей вкладке; разрешение сайта можно отозвать в настройках браузера.

## Частые задачи

- Цвета, фон, размеры и новые кнопки: сначала **Оформление**. Это безопаснее изменения React-кода и не требует новой веб-сборки для каждой настройки.
- Тема: найдите файл темы в `src/shared/ui`; проверьте обычный календарь, PRO, формы, настройки и мобильную версию.
- Ячейка календаря: `CalendarDayCell.jsx` и `CalendarDayCell.css`. Раскладка недель — `CalendarGrid.jsx`.
- Микрофон: `src/shared/ui/CalendarVoiceButton.jsx` (кнопка и поведение), `CalendarVoiceButton.css` (цвет/форма/размер). Кнопка внутри голосового окна — `VoiceWorkspace.jsx`. В карте есть отдельная карточка с этими ссылками.
- Текст: `src/shared/i18n`; затем поиск `copy`, `COPY`, `Copy` в нужном разделе.
- Новая возможность: найдите соответствующий feature. Не начинайте с большого `CalendarScreen.jsx`, если можно изменить узкий компонент.
- Вход: код в `auth`, но разрешённые URL и секреты OAuth меняются в Supabase/Google, не в браузерном коде.

## Проверка и выпуск: сохранение файла — ещё не публикация

Откройте терминал в корне проекта. Если зависимости уже установлены:

```powershell
npm run dev
```

Откройте адрес, который покажет Vite, и проверьте нужный экран. По умолчанию это `http://localhost:5173`; вход требует разрешённого callback-адреса в Supabase. Для общей карты можно просто читать этот документ офлайн. Подписка Codex для npm, Git и сайта не нужна.

Перед выпуском:

```powershell
git status --short
git diff
npm run build
node --test tests/site-config.test.mjs tests/admin-service-worker.test.mjs tests/project-files.test.mjs
```

Затем запустите тесты изменённого раздела. Для админки — `node tests/site-admin-ui-check.mjs` и `node tests/admin-users-ui-check.mjs`. UI-проверки в текущем проекте могут использовать Playwright из локального Codex runtime: без него понадобится самостоятельная установка Playwright и браузера/настройка пути. Сборка сама по себе не доказывает, что всё работает на телефоне или в облаке.

Когда проверка завершена, добавляйте только свои файлы (не весь проект вслепую):

```powershell
git add -- путь/к/изменённому/файлу
git diff --cached --check
git commit -m "Describe the change"
git push origin main
```

Render в текущем процессе выпуска собирает сайт из main. Проверяйте статус выпуска и сам HTTPS-сайт. Если установленный PWA показывает старый интерфейс, сначала полностью закройте и откройте его онлайн. Не подменяйте опубликованный `dist`: это результат сборки, исходники лежат в других папках.

SQL и Supabase Functions не применяются от редактирования файла или обычной Vite-сборки. Не переписывайте уже применённые миграции: делайте новую. Не выполняйте SQL без резервной копии и понимания воздействия. Android также требует отдельной сборки и выпуска.

## Ограничения и безопасность

### Как подключать новые модули к визуальному инспектору

`src/features/admin/siteConfig.js` содержит стабильные ID, подписи и CSS-селекторы элементов. `featureRegistry.js` рядом описывает смысл модуля, шаги его работы и связанные файлы. Для нового элемента нужен устойчивый селектор в компоненте, запись в ELEMENTS и описание в реестре. Не используйте текст кнопки как селектор: перевод или данные могут его изменить. Если нужен отдельный визуальный конструктор поведения, подключается собственная форма во вкладке «Логика» и безопасная модель данных — как `VoiceCommandsEditor` и `customVoiceCommands` у микрофона. Просто описание модуля не создаёт новую функцию и не выдаёт серверных прав. После изменений проверьте обычный экран, инспекцию, выполнение действия, телефон/ПК, сохранение и отсутствие обхода прав.

- Секреты `.env*`, ключи подписи, credentials/secrets, `.git`, SDK/JDK, Git, node_modules, dist/build и временные artifacts скрыты. Назначение этих папок объяснено отдельно.
- Не вставляйте пароли, API-ключи или service role в код клиента.
- Кошелёк, торговые сделки/PnL и инвестиционный капитал — разные данные. Не объединяйте их.
- Файлы более 1 МБ и бинарные файлы не редактируются. Lock-файл и генерируемые файлы доступны только для чтения. Некоторые изображения отображаются лишь как записи в дереве.
- В HTTPS-вкладке нет запуска команд. В локальной мастерской есть только фиксированные операции сборки/базовых тестов и подтверждённого Git-выпуска. Нет применения SQL, удаления/переименования файлов и произвольных shell-команд. Для больших рефакторингов используйте полноценный IDE.
- Карта обновляется при `npm run build` и перед `npm run dev`. Отдельно: `npm run project:map`. Не редактируйте `projectCatalog.generated.json` вручную.
- Чтобы новые папки/файлы появились в локальной мастерской, перезапустите `npm run project:desk`. Генерация карты во время сборки специально не перезагружает открытый редактор и не сбрасывает выбранную папку. Для мастерской нужны Node.js, зависимости проекта и Git; для push — настроенная авторизация Git.
- Проверка конфликта сравнивает текущий текст до записи, но это не межпроцессная блокировка IDE. Не сохраняйте один файл одновременно в двух программах.
- Любой браузерный редактор, которому вы дали папку, требует доверия к сайту. Отзывайте разрешение, когда закончите работу.
